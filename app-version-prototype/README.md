# App版本管理原型与需求文档

直接在浏览器中打开 `index.html`，不需要构建或安装依赖。

- `app.js`：现有原型交互及本地演示数据。
- `requirements.js`：需求目录及正文的唯一内容来源。
- `modes.js`：全局模式切换、目录渲染和 hash 定位。
- `modes.css`：切换入口与文档响应式样式，沿用原有配色。

## 维护需求

在 `requirements.js` 的模块 → 功能 → 需求点结构中新增或修改条目。需求点必须有稳定的 `id`、`number`、`title`、对应原型标签页 `tab`（`app` 或 `apk`）与 `description`。可选内容：`flow` 操作步骤数组、`fields` 字段与说明二元数组、`rules` 校验规则数组、`states` 异常与边界数组。目录自动生成；文本会转义，不在内容中编写 HTML。

当前整理日期为 2026-10-20；正文的更新时间指本次整理日期。后续修改时维护需求点的 `updated` 日期，未设置时沿用根模块的 `updated` 日期。仅根据现有实现整理，未知规则明确标为待确认。

## 定位与记忆

URL hash 包含 `mode`、`tab`、`req`，可复制当前文档链接。明确的 URL 模式优先于浏览器上次选择，无明确 URL 时读取 `sm-view-mode`，首次访问默认原型模式；`sm-doc-entry` 记录需求点。切换时保留当前标签页，原型筛选、分页及列表 DOM 保留；切换模式关闭当前抽屉，不自动保存未提交内容。

右下角入口支持鼠标、键盘和触屏。文档与原型可通过面包屑右侧快捷链接双向跳转。文档中上传需求提供边界状态验证入口，上传失败模拟控件不在原型演示中显示。
